# テーマ資金流入サマリー: 追加データ検討

## 前提

`/themes/summary` の MVP は、既存の `daily_prices`, `stock_master`, `themes`, `theme_stocks` だけで実装できる。

- 騰落率: `daily_prices.adj_close`
- 出来高: `daily_prices.volume`
- 売買代金: `daily_prices.turnover`
- ユーザー定義テーマ: `themes`, `theme_stocks`
- 業種分類: `stock_master.sector17`, `stock_master.sector33`

この MVP で判定できるのは「価格モメンタム」と「売買代金・出来高の増加」まで。実際の買い越し主体や信用需給までは判断できない。

## 追加データが必要になるケース

| 目的 | 必要な追加データ | できるようになること | 注意点 |
|---|---|---|---|
| 実際の買い越し・売り越しを見たい | 投資部門別売買動向、個別銘柄の主体別売買データ | 海外投資家、個人、自己売買などの資金流入を推定 | 個別銘柄単位で安定して取れるデータソースが必要 |
| 信用需給を見たい | 信用残、信用倍率、日証金速報 | 上昇が信用買い主導か、踏み上げ余地があるかを評価 | データ頻度、銘柄カバレッジ、取得ライセンスを確認する必要あり |
| 空売り圧力を見たい | 空売り残高、空売り比率、貸借取引データ | ショートカバー、売り圧力、逆日歩リスクを補足 | 日次更新だけでは場中変化は見えない |
| ニュース起点でテーマを自動生成したい | ニュース、適時開示、決算説明資料、テーマ辞書 | 「半導体」「防衛」「AI」などを自動分類 | 日本語テキスト分類と同義語辞書が必要 |
| 当日場中の資金集中を見たい | 分足、リアルタイム価格、リアルタイム売買代金 | 寄り付き後や場中の急な資金集中を検知 | JQuants の日足だけでは不可。別データ契約が必要 |
| 指数・ETFフローの影響を見たい | 指数構成銘柄、ウェイト、ETF売買・設定解約データ | 個別材料ではなく指数需給で動いている銘柄を判別 | 指数構成の更新頻度と権利関係に注意 |
| テーマ間の相対的な資金集中を厳密に見たい | 全市場の日次売買代金履歴、テーマ定義の網羅的マッピング | 市場全体に対するテーマ売買代金シェアを算出 | MVP でも近似可能だが、テーマ定義の品質に依存 |
| 需給イベントを検出したい | TOB、MSCI/FTSE入替、TOPIX浮動株比率変更、公募増資、自社株買い | 需給イベント由来の売買代金増加を区別 | イベントカレンダーと個別銘柄マッピングが必要 |

## 追加優先度

1. 信用残・貸借系
   - テーマの過熱感、踏み上げ、需給悪化を判断しやすい。
   - 日次/週次でも MVP の売買代金サマリーと相性がよい。

2. 適時開示・ニュース分類
   - テーマ作成を手動から半自動に拡張できる。
   - 既存の EDINET/開示タイムライン機能とも接続しやすい。

3. 分足・リアルタイム系
   - 場中検知には有効だが、データ取得・保存・UIの負荷が大きい。
   - 日足サマリーが固まってから検討する。

4. 投資主体別・ETFフロー
   - 解釈力は高いが、個別銘柄テーマ分析への接続にはデータ制約が多い。

## MVP から拡張する時の方針

- まずは既存日足データで「売買代金倍率」「出来高倍率」「騰落率」「上昇銘柄比率」を安定して出す。
- 次に信用残や空売りなど、日次または週次で保存できる需給データを追加する。
- テーマ自動生成は、手動テーマ機能とサマリー表示の利用感が固まってから行う。
- 追加データを入れる場合も、既存の `daily_prices` や `stock_master` の互換契約を壊さず、新規テーブル追加で進める。
